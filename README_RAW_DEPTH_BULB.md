# 原始深度胶头抓取诊断（独立实验）

`run_depth_bulb_grasp.py` 不调用服务器推理，也不修改旧滴液或三阶段 workflow。它在指定的 RGB 小区域中用红/粉色找到胶头，只保留该区域内的有效、连续原始深度；再用彩色相机内参、拍照时的 `T_base_tool0` 和本地手眼矩阵，把深度点反投影到 UR base。求得的是**相机看见的胶头表面点云中位数**，不是胶头完整体积中心。

## 先离线比较，不连接硬件

```bash
cd /home/dsj/vla/affordance
conda activate ur_data
python run_depth_bulb_grasp.py
```

默认读取最近一次成功解算的采集；也可指定：

```bash
python run_depth_bulb_grasp.py \
  --capture-dir captures/20260922_210124_502296
```

输出到该采集目录的 `raw_depth_bulb_diagnostic/`：

- `raw_depth_bulb_mask_overlay.png`：实际用于计算的颜色+有效深度点；
- `result.json`：原始深度表面中心、抓取目标、像素/深度有效数量和服务器 affordance 中心之差。

当前历史图像的 ROI 默认 `[345,110,400,185]`；如果相机或物体视角改变，用 `--roi X0 Y0 X1 Y1` 修改。`--depth-min/--depth-max` 用来排除无效深度和桌面背景。绿色小点标出所用像素的中位位置。

## 可选真机夹持测试

先由操作员把腕部相机安全地放到能看清胶头的观察位置，确认 ROI 仍包住红色胶头、夹爪为空、滴瓶和机器人工作区无障碍。然后运行：

```bash
python run_depth_bulb_grasp.py --live
```

这会连接 UR 和相机，在**当前位姿**拍一张新 RGB-D，但不会移动机械臂，也不会访问服务器。检查新目录中的遮罩和坐标后，若还要实际夹持：

```bash
python run_depth_bulb_grasp.py --live --execute
```

`--execute` 只能与 `--live` 一起使用。程序重新拍照，从当前位姿规划“原地抬升→胶头上方→下降”，在移动和闭爪前要求键入 `DEPTH GRASP`。它会闭合夹爪，但**不会抽出滴管、移动到烧杯或松爪**，便于现场直接看两指是否对中。若中途取消，程序不会自动释放可能夹住的物体。

默认抓取目标是原始深度表面中心向世界 Z 下移 `0.010 m`。可用 `--grasp-z-offset` 调整，但必须在真机检查指尖与玻璃瓶口的净空。夹爪开度使用 `config/three_stage_demo.yaml` 的 `dropper.hold_position`。

## 当前数据能说明什么

对 `20260922_210124_502296`，原始深度可见表面中心约 `[0.5458,-0.1744,0.1914] m`，服务器胶头 affordance 中心约 `[0.5453,-0.1741,0.1878] m`，XY 差仅约 `[+0.5,-0.3] mm`。这说明**同一 RGB-D/手眼链上的两种方法在水平位置近似一致**，不支持服务器模型中心存在稳定 1–2 cm XY 误差的结论。但两者共用相机内参和手眼矩阵，因此即使真实抓取仍偏，也不能仅凭本实验区分手眼误差与夹爪 TCP/指尖中心误差；需要独立测量的标志点或手动示教对中位姿。

透明玻璃附近的深度会缺失或落到背景；程序通过粉红色掩码、深度范围和连续深度筛掉这类点。ROI 与颜色阈值是针对当前场景的诊断参数，不是通用胶头检测模型。
